# フェーズ 27: 画像処理機能の強化 ✅
> **目標**: Markdown の相対パス維持しながら、エディタ上での即時プレビューを実現する

## 背景
これまで、Markdown 内で相対パス（例: `assets/image.png`）が指定されている場合、Webview プロセスのセキュリティ制約により画像が表示されない課題がありました。また、画像を挿入した際に絶対パスで記録されてしまうと、他のPCで開いた際に画像がリンク切れになる（ポータビリティの欠如）問題がありました。

## 実装内容

### 1. 双方向パス変換システム
- **読み込み時 (Markdown -> HTML)**:
  - `markdown-parser.ts` にて、`img` タグの `src` が相対パスである場合、メインプロセスの RPC (`readImageAsDataUrl`) を介して Base64 データ URL に変換します。
  - 元の相対パスは `data-original-src` 属性に退避させます。
- **保存時 (HTML -> Markdown)**:
  - 保存直前に `src` を `data-original-src` の値（相対パス）で上書きし、データ URL を除去します。

### 2. メインプロセス (Bun) の拡張
- `readImageAsDataUrl` RPC ハンドラーの実装:
  - `node:fs/promises` の `readFile` を使用し、ローカルファイルを読み込んで適切な MIME タイプの Data URL を返します。

### 3. エディタ (Tiptap) のカスタマイズ
- Image 拡張を拡張し、`data-original-src` 属性を HTML 属性として保持できるようにしました。
- ドラッグ＆ドロップ、貼り付け、およびツールバーからの画像挿入時に、直ちにデータ URL で表示しつつ、バックグラウンドで `assets/` フォルダへ保存・相対パス化するフローを確立しました。

### 4. 操作性の向上
- ツールバーに画像挿入用の専用ボタンを追加。
- スラッシュコマンド `/image` に対応。
- 再パース (Syntax Refresh) 時にも、画像を非同期に再解決するように修正。

## 完了条件

- [x] 保存された Markdown ファイル内の画像パスが相対パス（`assets/...`）として維持されている。
- [x] 新規挿入した画像が即座に表示され、`assets/` ディレクトリに保存される。
