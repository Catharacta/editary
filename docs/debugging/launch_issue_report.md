# 起動失敗の履歴とトラブルシューティング・レポート (Editary / Windows)

このドキュメントは、Editary アプリケーションの Windows 環境における初期の起動失敗に関する原因と解決策を記録したものです。将来の同様のミスを防止し、デバッグの指針とすることを目的としています。

## 1. ショートカットの作業ディレクトリ不備 (Working Directory Issue)
- **事象**: インストール後のショートカットから起動すると「ファイルが見つからない」エラーまたはサイレントクラッシュが発生。
- **原因**: NSIS/WiX の設定において、ショートカットの `WorkingDirectory` がアプリケーションのルートではなく `bin` フォルダに設定されていた。
- **背景**: Electrobun の内部パス解決がカレントディレクトリを基準に `../Resources` 等を探す際、`bin` から開始するとリソースが見つからなくなる。
- **解決策**: ショートカットの作業ディレクトリを常にアプリケーションのインストールルート ($INSTDIR) に設定するようにインストーラーテンプレートを修正した。

## 2. ESM 形式での `require` 使用エラー (ESM ReferenceError)
- **事象**: バイナリを実行しても即座に終了し、何も表示されない。
- **原因**: `bun build` が生成する `index.js` は ES Module (ESM) 形式だったが、後付けで挿入したブートストラップコードで `require('path')` を使用していた。
- **背景**: ESM フォルダ/ファイル内では `require` はグローバル変数として定義されていない。
- **解決策**: グローバルな `process.env` と文字列連結のみを使用した、外部モジュールに依存しないブートストラップコードに切り替えた。

## 3. 巨大ファイル操作時のメモリ汚染 (In-place Edit Corruption)
- **事象**: バイナリが起動途中でハングアップ、または意味不明な文字列がログに出力される。
- **原因**: `scripts/fix_build.ts` において、5.5MB を超える `index.js` を `readFileSync` で読み込み、文字列結合して `writeFileSync` で上書きする際、バッファ管理の限界から「ビルドスクリプト自体のコード」や「関係のないメモリ断片」が JS の中に上書きされた。
- **背景**: Node.js/Bun の文字列操作において、非常に大きなファイルを同期的に上書き保存する際のメモリアライメントやエンコーディング処理が不安定になった可能性がある。
- **解決策**: 一時的なファイルを作成して結合し、完成後に元のファイルを置き換える方式（アトミックな書き込みに近い手法）を採用した。

## 5. 管理者権限とインストール先ディレクトリの不整合 (Permission & Path Issue)
- **事象**: `C:\Program Files` にインストールした後、アプリが正しく起動しない、または特定の動作（設定の保存や自己更新など）でクラッシュする。
- **原因**: アプリケーションの一部がインストールディレクトリへの書き込み権限を必要としていたが、`C:\Program Files` は標準ユーザーには書き込み権限がないため、実行時にエラーとなっていた。
- **背景**: Electrobun のランタイムや Bun が内部で一時的なファイル作成やディレクトリ操作を行う際、管理者権限を想定したパス構成になっていた可能性がある。
- **解決策**: インストール先を `%LOCALAPPDATA%`（ユーザー別ディレクトリ）に固定し、管理者権限を要求しない「ユーザーレベル・インストール（Route B）」に移行した。
- **WiX/NSIS の修正**: 
    - NSIS: `RequestExecutionLevel user` を設定。
    - WiX: `InstallScope="perUser"` と `InstallPrivileges="limited"` を適用し、レジストリを `KeyPath` とすることでバリデーションエラーを解消した。

## 再発防止用チェックリスト
- [ ] 配布用 `index.js` の冒頭 10 行に `require` が含まれていないか？（ESM の構文エラー回避）
- [ ] `Resources/app/bun/index.js` に `update.bat` や `scripts/` の断片が混入していないか？（汚染チェック）
- [ ] 実行バイナリと同じ `bin` フォルダ内に、`bun.exe` と共に `webgpu_dawn.dll`, `WebView2Loader.dll` が存在するか？
- [ ] インストーラーが生成するショートカットの作業ディレクトリが「ルート」になっているか？
- [ ] インストール先が `%LOCALAPPDATA%` になっており、UAC（管理者権限）を要求せずにインストール可能か？
- [ ] WiX ビルド時に `candle.exe` / `light.exe` のパスが引用符で囲まれ、`shell: true` で実行されているか？（Windows パス空欄/スペース対策）
- [ ] WiX コンポーネントに `Guid="*"` ではなく、安定した静的 GUID が付与されているか？（CNDL0230 回避）
